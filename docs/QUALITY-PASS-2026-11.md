## 1. データが失われる・同期が止まる

### 1-1 送れない編集 1 件で送信待ち全体が止まる（直した）
- **起きること**：サーバーが受け付けない編集（引数不正、1 行に収まらない大きさ）が 1 件あると、その push が毎回失敗し、後ろの編集がすべて永久に送られない。
- **なぜ**：50 件まとめて送る push が例外で落ちると、同じ束を次の回も送っていた。
- **直し方**：失敗したら先頭 1 件だけで送り直し、3 回失敗したものは脇に置いて（`outbox.stuck`）残りを送る。バッジに「送れない編集があります」、通知の「もう一度送る」で再送。開いているメモの編集は 900KB ごとに分割して保存・送信。サーバーは 900KB 超の更新を例外ではなく `tooLarge` で拒み、クライアントはそれを捨てずに脇に置く。
- **確かめ方**：`tests/outbox-stuck.test.ts`、`tests/docs.test.ts`（分割）、`convex/sync.test.ts`（`tooLarge`）。

### 1-2 端末の時計が進んでいると、作ったメモと本文が消える（直した）
- **起きること**：時計が 1 分以上進んだ端末で作ったメモがサーバーに拒まれ（clockSkew）、3 回で捨てられ、その本文の更新も「メモが無い」として捨てられる。
- **なぜ**：拒まれたものを同じスタンプのまま再送し、諦めると削除していた。補正後も、進んだ時計が残した「最後のスタンプ」からの連番を使っていた。
- **直し方**：補正後の時計で打ち直して即再送（作成は決して捨てない）。`syncClock`/`loadClock` が進みすぎた最後のスタンプを補正後の時刻に戻す。作成がまだ届いていないメモの更新は、メモがある限り待つ。
- **確かめ方**：`tests/clock-skew.test.ts`、`tests/clock.test.ts`。

### 1-3 写真を貼った直後にスマホが止まると写真が永久に消える（直した）
- **起きること**：アップロードは済んだのに「確定」が 1 時間以内に届かないと、サーバーが予約を切って写真を消し、メモには存在しない写真が残る。
- **なぜ**：アップロード直後に端末側の複製（送信待ちの行）を消していたので、送り直す元が無かった。HTTP エラーも確認していなかった。
- **直し方**：確定がサーバーに受け取られるまで行と複製を残し（`storageId`/`commitOpId`）、拒まれたら複製から送り直す。`response.ok` と `storageId` の有無を確認。
- **確かめ方**：`tests/attachments.test.ts`、`tests/attachment-commit.test.ts`。

### 1-4 添付の確定が他の行のファイルを横取りする（直した・サーバー）
- **起きること**：別の添付・スナップショット・版が持つ `storageId` で確定でき、片方を消すともう片方のファイルも消える。
- **直し方**：`uploadedSize()` で確認し `storageInUse` で拒む。
- **確かめ方**：`convex/attachments.test.ts`。

### 1-5 同時の変更でスタンプが戻る／本文の到達位置が巻き戻る（直した）
- **起きること**：リネームと移動が同時に走ると片方のスタンプが元に戻り、他端末の値が一時的に勝つ。保存のたびに `bodies` を丸ごと書き、pull が進めた `throughSeq` を巻き戻すことがあった（圧縮やロックが止まる）。
- **直し方**：Dexie のキーパス（`"ts.title"` など）で自分の項目だけ更新。本文は `update` で変え、無ければ `put`。
- **確かめ方**：`tests/mutations-stale-ts.test.ts`、`tests/docs.test.ts`。

### 1-6 フォルダツリーで ← → を押すとフォーカスが消える（直した）
- **起きること**：E2E「arrow keys walk the folder tree」が失敗していた。
- **なぜ**：閉じたフォルダの行は素のまま、開いたフォルダの行は固定見出しのグループの中に描いていたため、開閉で行が別の親に移り React が作り直していた。
- **直し方**：閉じていても同じグループ構造で描く。
- **確かめ方**：`tests/folder-tree-nested.test.tsx`、E2E `notes.spec.ts`（41 件通過）。

### 1-7 即席メモの下書き画像が WebKit の再起動後に消える（直した・実機未確認）
- **なぜ**：IndexedDB から読んだ blob をそのまま書き戻していた（WebKit は再起動後にそうした blob で行を書くとファイルを失う）。
- **直し方**：`loadDraft` が返す画像をメモリ上の複製にする（`lib/media/blob-copy`）。
- **確かめ方**：`tests/quick-draft.test.ts`。Playwright の WebKit は IndexedDB にファイルを置けないので、実機（Mac アプリ）で：画像を貼る→アプリを終了→起動→即席メモに画像が残るか。

## 2. 入力の重さ（計測は冒頭の表）

- **送信のたびにシェル・サイドバー・エディタが描き直されていた**：サーバーが push ごとに使用量を書き、`users.me` が新しいオブジェクトになり、`useSync()` を読むすべてが描き直されていた。使用量を `me` から外し（identity を保つ）、`useStorageUsage()` と `useAllowance()` に分けた。`tests/sync-provider-profile.test.tsx`。
- **行が見た目の変わらない更新で描き直されていた**：`lastUpdateSeq` などで note が毎回新しくなり memo が効かなかった。表示項目だけで比べる（`lib/note-face`）。相対時刻は 10 秒の時計で進める（`use-clock`）。
- **見えていないサイドバーと一覧が全件を読んでいた**：スマホで隠れた PC 用サイドバー、開いたメモの裏の一覧。幅広のときだけ描く／`enabled` で一時停止。バックリンクは `bodies.*links` の索引（DB version 2）。
- **1 打鍵ごとの全文走査**：`listFromMarks`（変更範囲だけ見る）、`emptiedToggles`（開いたトグルが無ければ何もしない）、`stuck-toggles`（文字の変更を監視しない、トグル外では位置を測らない）、`MobileBlockToolbar`（キーボードが上がっているときだけ中身を mount）。
- **エコーごとの全メモ走査**：`settleAllNoteTitles` は名前かフォルダが変わったメモがあるときと起動後 1 回だけ。
- **見送り**：フォルダ行の memo 化（P4）。上の修正で PC の数値が十分良くなったため（p95 21ms、長い処理 0 回）。

### 画像の worker 化
貼った画像の読み込み（`createImageBitmap`）、判定（平坦さの標本）、縮小の描画、WebP の書き出しをすべてページのスレッドで行っていた（Chrome では `canvas.toBlob`、Safari は `getImageData` のあと WebAssembly の worker）。worker に File を渡し、worker が `createImageBitmap` → `OffscreenCanvas` に描画 → `convertToBlob`（WebP が書ける Chrome/Firefox）、書けなければ libwebp（Safari）、それも無理なら PNG/JPEG。縮小の段取り（大きさ・回数・品質・元を残す判断）は `lib/media/prepare-plan` に切り出し、ページと worker で同じものを使う。WebAssembly は初めて必要になったときだけ読み込む。worker が使えない・失敗した・遅いときは従来の経路に落ちる（既存の「2 回失敗で 5 分使わない」規則を共有）。効果は上の表。Safari（iPhone の PWA、Mac アプリ）での実測は未実施。確かめ方：`tests/prepare-in-worker.test.ts`、E2E `webp-worker`/`image-kinds`/`convert-images`/`image-crop`/`uploads`/`quick-images`/`csp`（20 件通過）。

## 3. 記法（日本語入力のまま使える）

- `ー`/`－`/`‐`/`−`/`＊`/`＋` + 空白（全角可）→ 箇条書き、`１．`/`1。`/`12．` + 空白 → 番号付き（その番号から）、`「」` + 空白 → チェック項目、`「x」`/`「×」`/`「✓」` → チェック済み、`•` 単独 → 箇条書き。`１、` と `①` は変えない。変換中は動かず確定後に効く（`CompositionEvent` のテストあり）。
- `「` + 空白で引用になる BlockNote の規則を外した（`> ` と ⌘⌥Q は残す）。
- チェック済み項目の先頭で Enter：空の項目を上に入れ、文はチェックと番号を保つ。
- 閉じたトグルの行頭で Backspace：開くだけ。
- 確かめ方：`tests/lists.test.ts`（新規 7 件、修正前は失敗）、E2E `japanese-lists`/`toggles`/`lists`。

## 4. IME（Mac デスクトップ版、メモリ逼迫時）

症状「即席メモで打った文字が次の文字を上書き／消せない／保存されない／窓を閉じて開くと直る」は実機の記録がないと原因を特定できない。どの原因でも取り戻せるようにした：
- 入力欄を React の制御から外し（`defaultValue`）、React が古い値を書き戻す経路を断つ。`readOnly` もやめ、保存中に打った文は「保存済み」にせず下書きに残す。
- 見張り（`lib/quick/field-watchdog`）：欄の値とアプリの持つ文がずれていれば欄から伝え直す。変換が始まったまま 2 秒以上何も来なければ記録して `blur/focus` で揺り起こす（窓の開閉と同じ効き目）。
- `ime-commit` の修復は、確定直後にまだ変換中でも 50ms × 20 回まで試す。
- 確かめ方：`tests/quick-capture.test.tsx`、`tests/field-watchdog.test.ts`、`tests/ime-commit-retry.test.ts`。**実機のエンジン停止そのものは検証できていない。** 再発したら ⌘⌥⇧I で記録を取ると、`quick:desync` / `quick:stuck-composition` のどちらが出たかで原因が絞れる。

## 5. サーバー（Convex、追加のみ。本番は push で自動デプロイ、事前に `~/memoca-backups/memoca-2026-11-08-1242-before-quality-pass.zip` を取得）

- `applyUpdateOp` の `tooLarge`、`applyAttachmentCommit` の `storageInUse`（上記）。
- 確かめ方：`convex/sync.test.ts`、`convex/attachments.test.ts`、`tests/apply.test.ts`、`tests/compact-large.test.ts`。

## 6. そのほか

- 複数ファイルの貼り付け・ドロップで 1 枚目しか入らない（BlockNote が `await` の後に `dataTransfer.items` を読み直す）：`@blocknote/core` にパッチ（`patches/@blocknote__core@0.55.0.patch`）。1 枚の拒否で残りが止まらない。`tests/paste-many-files.test.ts`、E2E `uploads.spec.ts`。
- スマホで長いメモの終わりを打つとキャレットがキーボードの下に隠れる（Playwright の模擬で確認）：原因は 2 つ。ブラウザはキーボードで縮まないレイアウト上の可視範囲にキャレットを合わせること、そしてメモの末尾の下に余白がなく、最後の行をキーボードより上へ送れないこと。キーボードが上がっている間はメモの下にキーボード＋ブロックバーの高さの余白を置き（`--memoca-keyboard-room`、MobileBlockToolbar が設定）、変更のたびにキャレットを `visualViewport` とブロックバーの上端と比べて、隠れた分だけページを送る（`caret-above-keyboard`）。実機の iPhone でも確かめたい。
- URL をそのまま貼ってもリンクにならなかった：BlockNote の「貼り付けでリンク」は、BlockNote 自身の貼り付けハンドラが先にイベントを取るため動いていなかった。URL 1 つだけの貼り付けは、何も選んでいなければその URL へのリンクとして、文字を選んでいればその文字をリンクにする（`paste-link`）。`、。` が続く文やコードブロックの中、Memoca 自身のコピーは従来どおり。`tests/paste-link.test.ts`。
- 変更履歴の「戻す」で、戻す前の版の保存に失敗しても「残っています」と出ていた：結果で文言を分ける。
- 初回ログインでアカウント作成（`users.ensure`）がサーバーの混雑などで失敗すると、再試行せず、読み込み画面のまま止まっていた（E2E で手元の Convex が過負荷のときに見つかった）：2 秒×回数の間隔で最大 6 回まで試す。`tests/sync-provider-profile.test.tsx`。
